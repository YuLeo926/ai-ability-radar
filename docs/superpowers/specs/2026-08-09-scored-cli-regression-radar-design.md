# Codex CLI / Claude Code 本地计分回归雷达设计

日期：2026-08-09
状态：已由用户逐段确认

## 1. 背景与结论

当前项目已经具备本地界面、CLI 发现、隔离工作区、题包哈希、历史记录、批次分析、报告导出和 Windows 便携打包等基础设施，但现有 `client-quick` 的 8 道单轮题和 `cli-quick` 的 2 个微型项目区分度不足。实测中不同能力档位均可一次满分，说明统计与展示层已经超过测量层的有效性。

本设计把产品收缩为“Codex CLI / Claude Code 本地能力回归雷达”。首版不再扩展 ChatGPT 或 Claude 桌面客户端，也不把完整 DeepSWE 当作默认题包。执行层优先复用 Promptfoo 已有的 Codex SDK、Codex app-server 和 Claude Agent SDK 接入；项目自身聚焦于中文本地界面、困难题包、确定性评分、历史基线和解释性报告。

参考项目与方法：

- [CodexRadar](https://codexradar.com/)：真实仓库任务、近期多次结果、任务权重和 0～150 展示刻度；
- [Promptfoo](https://github.com/promptfoo/promptfoo)：Codex/Claude Agent 执行、重复评测、断言、轨迹和本地结果页面；
- [Drift Harness](https://github.com/jordan-drake/Drift_Harness)：噪声基线、重复实验、效应门槛和统计判断；
- [DFAH-Bench](https://github.com/ibm-client-engineering/output-drift-financial-llms)：Agent 最终结果与工具轨迹的重复性分离。

这些项目只提供方法参考。首版题目、验证器和评分规则由本项目独立设计，不复制第三方私有题目或评分数据。

## 2. 产品目标

首版必须完成以下目标：

1. 使用本机已有的 Codex CLI 或 Claude Code 登录状态运行测试；
2. 在 Windows 上以 JavaScript/TypeScript 题包完成一次 30～60 分钟的快速测试；
3. 通过 5 道固定混合工程题产生 0～100 原始能力分和 0～150 雷达 IQ；
4. 对核心功能、边界条件、回归兼容、约束遵守和工程完整性提供部分分；
5. 把登录、网络和运行器故障与 Agent 能力失败分离；
6. 在本机保存可复核的补丁、测试证据、轨迹和历史；
7. 在样本足够时，把当前能力与冻结历史基线比较；
8. 将能力、耗时、Token、额度和 Agent 步骤分别报告，不混合成一个分数。

## 3. 非目标

首版不提供以下能力：

- 不测试 ChatGPT 或 Claude 桌面客户端；
- 不声称识别提供商内部实际路由或底层隐藏模型；
- 不把一次低分直接宣称为“模型被替换”或“官方降智”；
- 不自动上传结果，不建设公共排行榜；
- 不用另一个大模型进行主观判分；
- 不默认运行完整 DeepSWE、SWE-bench 或多语言大型基准；
- 不把速度、价格、Token 或步骤数计入能力分；
- 不在同一题包版本内静默修改题目、权重或评分含义。

## 4. 总体架构

系统分为六个边界清晰的组件：

### 4.1 本地界面

负责选择目标、模型、推理档位和题包，显示免费预检、额度确认、实时进度、结果、历史和导出入口。界面不直接执行 Agent，也不包含评分事实。

### 4.2 执行适配层

优先通过固定版本的 Promptfoo 调用：

- Codex SDK 或 Codex app-server；
- Claude Agent SDK（别名 Claude Code）；
- 本地已有登录状态，或用户明确配置的 API 认证。

Promptfoo 负责进程生命周期、工作目录、线程、工具轨迹、Token 和基础运行元数据。应用不连接正在打开的 Codex Desktop 窗口；Codex app-server 由评测进程独立启动。

### 4.3 题包加载器

负责校验题包清单、版本、内容哈希、固定依赖、仓库快照和验证器身份。题包内容一旦发布即不可变；任何题目、权重或评分规则变化都必须发布新版本。

### 4.4 隔离执行器

每道题创建新的临时工作区。Agent 只看到任务快照和任务说明，不能读取隐藏测试、评分配置或其他题目的文件。首版默认禁用网络安装依赖，任务串行运行。

### 4.5 确定性验证器

验证器在 Agent 工作区外运行，通过隐藏单元测试、集成测试、静态约束和补丁范围规则产生结构化分项结果。相同工作区状态必须得到完全相同的分数。

### 4.6 历史与分析引擎

保存完整本地证据，计算单次分数、临时基线、冻结稳定基线、历史差异和证据标签。公共 JSON/HTML 导出不包含本机路径、登录数据或秘密。

## 5. 端到端数据流

1. 用户选择目标、模型、推理档位和快速题包；
2. 应用执行不消耗模型额度的本地预检；
3. 应用展示任务启动数、最长时间和可能消耗的用户订阅额度；
4. 用户明确确认后，应用冻结本次运行计划；
5. 题包加载器校验全部内容；
6. 隔离执行器为当前题目创建干净工作区；
7. Promptfoo 启动 Codex 或 Claude Agent；
8. Agent 完成修改或达到受控预算；
9. 验证器在工作区外执行并生成分项证据；
10. 当前题结果立即持久化，再进入下一题；
11. 五题全部结束后生成正式总分；
12. 分析引擎查找完全匹配的历史系列并生成历史变化标签；
13. 界面显示能力、效率、证据和环境信息。

## 6. 快速混合题包

首版题包固定包含 5 道 JavaScript/TypeScript 工程题，目标总时长为 30～60 分钟，每题最长 12 分钟。

| 题目 | 来源 | 主要能力 |
| --- | --- | --- |
| 异步并发与状态泄漏修复 | 裁剪真实开源项目 | 定位、并发正确性、边界处理 |
| 跨文件 API 功能实现 | 裁剪真实开源项目 | 需求理解、跨模块修改、测试驱动 |
| 缓存、配置与向后兼容修复 | 裁剪真实开源项目 | 回归控制、兼容性、状态管理 |
| 多约束重构 | 原创工程场景 | 约束遵守、最小修改、行为保持 |
| 重试、取消、幂等与异常恢复 | 原创工程场景 | 鲁棒性、故障恢复、复杂控制流 |

真实项目以固定提交的裁剪快照分发，保留许可证和第三方声明。依赖提前锁定并准备，不允许测试时临时联网安装。原创题使用真实项目结构和工具链，不使用只有几十行代码的玩具实现。

每题必须包含：

- 明确但不泄露验证器的任务说明；
- 可运行的初始项目；
- 核心功能隐藏测试；
- 边界和异常隐藏测试；
- 回归兼容测试；
- 静态约束和补丁范围检查；
- 标准实现、缺陷变体和评分预期。

## 7. 每题混合计分

每题满分 100 分：

| 分项 | 分值 | 判定方式 |
| --- | ---: | --- |
| 核心功能 | 40 | 隐藏功能与集成测试 |
| 边界与异常处理 | 25 | 边界、并发、错误路径测试 |
| 回归兼容 | 15 | 既有行为、API 和数据兼容测试 |
| 约束与修改范围 | 10 | 静态规则、允许文件和差异检查 |
| 工程完整性 | 10 | 构建、类型、交付文件和确定性检查 |

限制规则：

- 每题清单必须标出不可替代的核心断言。任一不可替代核心断言失败，或核心功能断言通过率低于 50% 时，视为核心功能未达到最低要求，单题最高 35 分；
- 候选修改导致项目无法构建或验证器无法进入测试阶段时，单题最高 15 分；
- 删除或篡改受保护测试、绕过验证器、越界读取评分材料、写死隐藏答案时，该题为 0 分；
- 登录、网络、运行器或预置依赖损坏属于基础设施无效，不计为 0 分；
- Agent 达到时间、轮次或输出预算属于能力失败，按已产生的可验证结果计分。

首版不使用 LLM judge。所有部分分必须能由代码和固定规则复算。

## 8. 总分与展示刻度

首版五题等权：

```text
原始能力分 = 五道有效题目分数的算术平均
雷达 IQ = 原始能力分 × 1.5
```

两个分数均保留一位小数。原始能力分范围为 0～100，雷达 IQ 范围为 0～150；原始能力分 66.7 对应雷达 IQ 100。雷达 IQ 必须标注为“本题包跑分刻度”，不得描述为心理测量 IQ。

正式总分要求五题均有有效结果。题包未完成时可以显示阶段成绩，但阶段成绩不得写入正式历史基线。

结果页同时展示五个分项维度。耗时、Token、额度、Agent 步骤和工具轨迹独立展示，不参与原始能力分或雷达 IQ。

## 9. 历史系列身份

只有以下字段完全匹配的结果才能进入同一历史系列：

- 目标：Codex CLI 或 Claude Code；
- 请求模型与可见模型身份；
- 推理档位；
- 题包 ID、版本和内容哈希；
- 评分规则版本；
- Promptfoo 执行契约版本；
- 干净运行或恢复运行状态。

操作系统、CLI 版本、账号路由、登录方式和关键环境变化必须保存。它们不自动拆分能力系列，因为本工具测量的是用户看到的端到端 Agent 表现；发生变化时，结果页必须显示“环境已变化”，并禁止把变化单独归因于底层模型。

## 10. 基线生命周期

### 10.1 无基线

首次运行立即生成当前分数，但只显示“尚无基线”。

### 10.2 临时基线

同一历史系列达到 3 次完整有效运行后，按每题历史中位数建立临时基线。临时基线可显示差异，但不能生成“很可能退化”。

### 10.3 稳定基线

同一历史系列至少有 5 次完整有效运行，且覆盖至少 3 个不同本地日期后，按每题历史中位数建立稳定基线并冻结。稳定基线不会随新低分自动下移。

用户可以明确发起“重建基线”，但必须看到将使用的运行集合并再次确认。旧基线和其哈希永久保留，历史报告注明使用了哪个基线。

题包版本变化后建立新的历史系列和新基线，不跨版本拼接分数。

## 11. 历史变化信号

候选窗口为最近 3 次完整、有效且身份匹配的运行。稳定基线使用冻结时入选的至少 5 次运行。

信号级别：

1. **尚无基线**：历史不足；
2. **观察到波动**：单次结果低于基线，或候选窗口不足 3 次；
3. **持续异常**：最近 3 次的中位原始能力分同时满足绝对下降至少 6 分、相对下降至少 8%，并且至少 3 道题的中位分数同方向下降；
4. **很可能退化**：满足“持续异常”，使用稳定基线，并且固定种子的 2,000 次分层 Bootstrap 所得 95% 差值区间上界小于 0；
5. **证据不足**：有效样本不足、环境变化较大、排除比例过高或无法形成可比较分布。

Bootstrap 以题目为第一层抽样单位，在每道抽中的题内分别对候选运行与基线运行重采样，再计算总分中位差。不能把同一次运行中的五道题当作十五个相互独立样本。

所有信号只描述本工具在匹配端到端条件下记录的表现，不证明提供商内部发生了模型替换。

## 12. 免费预检与授权

开始测试前必须完成以下本地只读检查：

- Codex 或 Claude 执行入口；
- 本地登录状态可供 SDK/CLI 使用；
- Node、Promptfoo 和可选 Agent SDK 版本；
- 题包、仓库快照和验证器哈希；
- 磁盘空间、临时目录和执行权限。

预检不得调用模型。预检完成后显示：5 次任务启动、最长 60 分钟、预计最大 Agent 预算以及“消耗当前用户自己的订阅额度或 API 费用”。只有用户明确确认后才能越过 provider 边界。

## 13. 调度、取消与恢复

- 五道题串行执行，不并发争夺订阅额度；
- 每题在独立工作区和独立会话中运行；
- 当前题完成后立即保存原始证据和结构化结果；
- 用户取消时阻止后续题目启动，并终止当前受控进程；
- 恢复运行复用原 run ID，只继续尚未完成且从未越过 provider 边界的题目；
- 已经可能发送过模型请求但结果未知的题目不得自动重放；
- 恢复前重新展示剩余预算并取得确认；
- 只有五题全部形成有效结果后才生成正式总分。

## 14. 失败分类

| 类型 | 示例 | 是否计分 |
| --- | --- | --- |
| 基础设施无效 | 登录失效、网络中断、运行器崩溃、预置依赖损坏 | 否 |
| Agent 预算失败 | 超时、轮次上限、输出预算耗尽 | 是，按可验证结果 |
| 任务能力失败 | 测试失败、边界遗漏、兼容性破坏 | 是 |
| 规则违规 | 篡改测试、越界读取、绕过验证器 | 是，0 分 |
| 用户取消 | 用户主动停止 | 否，不生成正式总分 |

验证器必须 fail closed：证据缺失、身份不匹配、非有限分数或哈希错误均不得进入能力分或基线。

## 15. 本地数据与隐私

默认保存：

- 运行计划和环境身份；
- Agent 最终文本；
- 文件补丁；
- 命令与工具轨迹的安全摘要；
- 隐藏测试的通过标识和分项分数；
- Token、时长、步骤和退出状态；
- 基线快照、统计参数和结果。

不保存或导出登录 token、API 密钥和完整环境变量。所有结果默认仅在本机。首版不包含自动上传、匿名遥测或社区排行榜。

## 16. 题包校准与发布门槛

每个候选题包在发布前必须满足：

1. 标准答案稳定取得 95 分以上；
2. 人工缺陷变体分别覆盖低、中、高部分分；
3. 同一补丁重复评分完全一致；
4. 至少 4 个可见模型/档位组合参与校准，覆盖较低和较高能力配置；
5. 每个组合对每道题至少重复 3 次；
6. 参考配置的原始能力分跨度至少为 20 分；
7. 不允许所有配置都接近满分或全部失败；
8. 每道题不能长期呈现全通过或全失败；
9. 基础设施失败率低于 5%；
10. 快速题包实测中位时长保持在 30～60 分钟。

不满足区分度门槛的题目必须替换或提高难度，不得依靠修改显示比例制造差异。

校准结果冻结到题包发布记录中。以后调整题目权重必须发布新版本；旧成绩不得用新权重重算。

## 17. 自动化验证

实现必须包含：

- 题包 schema、哈希和许可证测试；
- 每个验证器的标准答案、空修改和缺陷变体测试；
- 分项计分、硬上限和违规归零测试；
- 基础设施无效与能力失败分类测试；
- 隔离工作区和隐藏验证器不可见测试；
- 取消、恢复和 provider 边界测试；
- 原始能力分、雷达 IQ 和舍入测试；
- 临时基线、稳定基线、冻结和重建测试；
- 分层 Bootstrap 与固定种子重现测试；
- 本地报告隐私和 schema 测试；
- Promptfoo/Codex/Claude 的假入口契约测试；
- 至少一次真实 Codex 本地登录的受控验收。

## 18. 现有项目迁移

保留：

- Tauri/网页界面与 Windows 便携包装；
- 本地历史数据库和证据存储；
- 题包注册、版本和哈希机制；
- 报告导出、删除和恢复语义；
- 批次计划、取消、预算确认和基础统计组件。

调整：

- 将当前 `client-quick` 和 `cli-quick` 标记为流程自检题包，不再产生正式能力分；
- 用新的 5 题 `cli-scored-quick` 题包替代正式快速测试；
- 把 Codex/Claude 自研执行适配逐步收缩为 Promptfoo 执行契约封装；
- 让现有评分器支持分项分数、硬上限和违规结果；
- 让历史页并列显示绝对能力和冻结基线差异。

不一次性删除旧适配器。先完成 Promptfoo 真实 Codex 验证，再按能力等价性逐步切换，以保留可回退路径。

## 19. 分阶段路线

### 阶段 1：执行底座验证

使用本机 Codex 登录，通过固定版本 Promptfoo 完成一个隔离任务，验证模型、档位、文件修改、轨迹、Token 和结果导出。不改变正式题包。

### 阶段 2：快速计分题包

实现 5 道 JavaScript/TypeScript 混合题、确定性部分分和 30～60 分钟快速模式。此阶段提供绝对能力分和雷达 IQ，但历史不足时不判断退化。

### 阶段 3：本地基线

实现临时基线、冻结稳定基线、候选窗口、分层 Bootstrap 和历史变化标签。

### 阶段 4：标准题包

在快速题包校准稳定后扩展到约 12 道任务，并加入 Python。标准模式用于更稳定的周期性检查，不替代快速模式。

### 阶段 5：完整题包

扩展到约 24 道任务和 JavaScript、TypeScript、Python、Go、Rust 五种语言。完整模式允许拆分到多次本地会话执行，适合校准与正式长期研究，不要求普通用户每次运行。

### 阶段 6：可选生态

只有在本地产品稳定、隐私设计和反作弊方案另行评审后，才讨论手动匿名贡献或公共聚合。该阶段不属于当前设计授权范围。

## 20. 成功标准

本设计成功的最低标准是：

- 用户可用本机 Codex 登录完成一次 30～60 分钟测试；
- 五题均产生可解释部分分和验证证据；
- 低、中、高能力参考配置不会普遍同分或满分；
- 能力分与速度、成本完全分离；
- 单次波动不会被误报为确定降智；
- 样本充足时能显示冻结基线差异和题目级变化；
- 所有原始证据留在本机；
- Windows 便携版和源码启动方式均可使用相同题包与评分逻辑。
