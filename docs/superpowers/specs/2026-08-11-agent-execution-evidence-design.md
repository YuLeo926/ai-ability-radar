# Agent 执行证据与验证状态分离设计

日期：2026-08-11
状态：已由用户逐段确认

## 1. 背景

一次受控 Codex CLI 验收暴露了明确缺口：Provider 返回了正常完成状态，但候选源文件没有发生变化，离线测试仍然失败。现有 Promptfoo 适配器已经取得 `final_text`、Token、工具类型和模型来源等证据，但 CLI 编排层在进入验证器前丢弃了结构化 `evidence`。结果页只能看到验证结论，无法解释 Agent 为什么没有完成任务。

这不是计分规则的问题。系统必须继续以确定性验证器作为能力结论来源，同时保存足够且受控的本地诊断证据，区分以下两个事实：

1. Agent 或 Provider 是否结束了一次执行；
2. 工作区最终状态是否通过任务验证。

官方 Codex SDK 将 `finalResponse` 作为线程运行结果返回，并说明 `workspace_write` 允许在工作区及配置的可写根目录内写入。项目使用的固定版本 Promptfoo 与 `@openai/codex-sdk` 还会在本地返回结构化 turn items。本设计只依赖固定版本中已通过契约测试确认的字段，不推断供应商未公开的实际模型路由。

官方参考：https://learn.chatgpt.com/docs/codex-sdk

## 2. 目标

本次改动必须实现：

- 保存脱敏后的 Agent 最终回答、工具错误摘要和命令退出状态；
- 保存文件修改事件数量、Token、耗时和模型证据；
- 明确区分 Agent 执行状态与验证器结果；
- 在本地结果页按需展示诊断详情；
- 让原始数据保留策略能够清理诊断正文，同时保留非敏感摘要；
- 让公共报告最多包含状态和计数，不包含正文、路径、命令或会话标识；
- 使用假 Provider 完成全部自动化验证，不再次消耗用户额度。

## 3. 非目标

本次不做：

- 不改变题目、隐藏测试、权重或计分公式；
- 不把 Agent 的完成文字当作任务通过；
- 不根据一次错误推断底层模型被替换或降智；
- 不保存完整命令、完整命令输出或绝对文件路径；
- 不增加网络上传、遥测或公共排行榜；
- 不发起新的真实 Codex 或 Claude 调用；
- 不改变超时任务的部分计分策略，该能力继续由原有执行计划单独实现。

## 4. 方案选择

采用“结构化证据文件 + 数据库摘要”。

未采用的方案：

- 全部写入数据库：查询简单，但会扩大数据库迁移面，使正文绕过原始数据保留策略；
- 打开页面时解析旧日志：改动少，但格式脆弱，无法恢复已被适配器丢弃的事件字段。

选定方案将私密正文保存在本地证据文件中，将稳定、非敏感、可查询的状态和计数保存到数据库。

## 5. 架构与组件

### 5.1 Promptfoo Runner

执行协议升级为 `promptfoo-agent-v2`。Runner 从固定版本 Provider 结果中产生一个严格、有限的诊断对象。

Codex 可使用的原始 item 类型包括：

- `agent_message`；
- `command_execution`；
- `file_change`；
- `error`。

Claude 使用固定版本 Provider 暴露的最终文本与工具元数据；无法由 Provider 证明的字段保持未知，不制造证据。

Runner 协议继续使用顶层 `status: success | error` 表示调用边界结果。只有 `success` 可以携带完整诊断证据；`error` 只携带受限的 Provider 错误分类，不能伪造一次已经完成的 Agent 执行。

成功响应中的标准化诊断包含：

- `final_text`：脱敏后的最终回答；
- `command_summary`：成功数、失败数、未知数，以及受限的退出码分布；
- `tool_error_summary`：错误类别与脱敏短文本；
- `file_change_count`：Provider 报告的文件修改事件数量；
- Token、耗时、会话是否存在、模型证据和 Provider 字段摘要。

`file_change_count` 只是执行轨迹，不证明文件最终正确，也不替代验证器。

### 5.2 Rust 适配层

Rust 对 `promptfoo-agent-v2` 执行严格反序列化和二次验证：

- 拒绝未知字段；
- 拒绝无效枚举、负数、非有限数值和不一致状态；
- 限制数组数量、文本字节数和退出码范围；
- Provider 错误响应不能携带伪造的成功证据；
- 模型来源与可见模型字段必须保持一致。

验证成功后，`AdapterCompletion` 携带结构化 `AgentExecutionEvidence`。Provider 正常结束只表示执行边界结束，不表示任务成功。

应用领域层另行派生 `AgentExecutionStatus`：`completed`、`provider_error`、`timed_out` 或 `cancelled`。它不是 Provider 自报字段：`completed` 只能来自通过协议验证的成功响应，其余状态来自适配器和编排层已经分类的终止原因。

### 5.3 CLI 编排层

CLI 编排层不再丢弃 `evidence`，而是：

1. 将结构化私密证据原子写入 `runs/<run-id>/evidence/<task-id>.json`；
2. 在 Agent 正常结束后运行现有确定性验证器；
3. 为每个新版本的终态任务保存一条 Agent 摘要；正常完成时引用证据文件，Provider 异常、超时或取消时只保存状态，不制造诊断正文；
4. 将验证器结果与 Agent 摘要作为两个独立事实保存；
5. 在证据文件或数据库检查点写入失败时清理本次新建文件，避免半条证据；
6. 对批次成员继续使用现有的原子隔离检查点，不拆开任务结果、隔离证明和 Agent 摘要。

### 5.4 数据库存储

新增迁移 `0004_agent_execution_evidence.sql` 和独立表 `task_agent_evidence`，以 `(run_id, task_id)` 为主键，并级联关联 `task_results`。

保存的数据库字段仅包括：

- Agent 状态；
- 可空的命令成功、失败和未知数量；
- 可空的工具错误数量；
- 可空的文件修改事件数量；
- Token 摘要；
- 模型证据；
- Provider 摘要；
- 本地证据相对路径；
- 证据契约版本。

最终回答、错误正文、命令内容、命令输出、绝对路径和完整会话 ID 不进入数据库。

新版本写入任务终态时，`task_results` 与 `task_agent_evidence` 必须在同一事务提交，因此新记录缺少 Agent 摘要属于存储损坏并按恢复规则处理。旧数据库打开时自动创建新表；迁移前的旧任务没有对应记录时显示“旧版本未记录”，不改变原有得分、状态和历史系列身份。

### 5.5 本地 API 与界面

`RunDetailDto` 返回 Agent 摘要，不返回诊断正文。新增按需读取命令，输入 `run_id` 和 `task_id`，后端从数据库取得受信任的相对路径并在 artifact root 下读取证据。

按需读取必须：

- 拒绝绝对路径、父目录组件和非预期扩展名；
- 拒绝重解析点或逃离 artifact root 的路径；
- 对缺失、已清理或校验失败的文件返回稳定的“详情不可用”状态；
- 不通过错误消息回显本机路径。

结果页每题显示两个独立状态：

- `Agent 执行`：已结束、Provider 异常、超时、已取消或旧版本未记录；
- `任务验证`：通过、部分通过、失败或无效。

“本地诊断详情”默认折叠。展开后显示最终回答、命令状态计数、退出码分布、工具错误摘要、文件修改事件数、Token 和模型来源。验证器结果保持最醒目的结论。

## 6. 隐私与脱敏

所有可保存文本在 Node 层进行一次脱敏，在 Rust 层进行长度和控制字符验证。

固定处理包括：

- 已知 API key、Bearer、Basic、云访问密钥和常见凭据赋值模式替换为 `<redacted>`；
- Windows 盘符路径、UNC 路径和 Unix 绝对路径替换为 `<path>`；
- 删除 NUL 和其他不允许的控制字符；
- 最终回答、单条错误和错误数量使用独立上限；
- 不保存命令正文、聚合命令输出和文件路径列表。

脱敏不能证明识别所有可能的秘密。因此诊断正文始终被视为本地私密原始证据：

- 不自动上传；
- 不进入公共报告；
- 不进入运行列表摘要；
- 可由原始数据保留策略删除。

删除或过期清理诊断文件后，数据库将证据相对路径置空，但保留状态和计数摘要。

## 7. 状态与失败语义

| Agent 边界 | 验证器 | 最终含义 |
| --- | --- | --- |
| 正常结束 | 通过 | 任务通过，可正常计分 |
| 正常结束 | 部分通过 | 能力结果，按确定性规则部分计分 |
| 正常结束 | 失败 | 能力失败，按规则计分；显示本地诊断 |
| 正常结束且含工具错误 | 通过 | 任务通过，同时提示工具轨迹存在错误 |
| Provider/Runner 基础设施错误 | 未运行或无效 | 基础设施无效，不计 0 分 |
| 超时 | 按现有超时规则 | 显示超时；是否部分计分仍由确定性验证器和既有规则决定 |
| 证据协议损坏 | 未运行 | 基础设施无效，fail closed |
| 用户取消 | 不采用晚到结果 | 取消，不计分 |
| 旧记录无 Agent 证据 | 保留旧结论 | 显示“旧版本未记录” |

任何 `turn completed`、`finalResponse` 或 Agent 自述“已完成”都不能覆盖验证器结论。

## 8. 公共报告

公共报告升级兼容版本，只允许增加：

- Agent 状态；
- 命令成功、失败和未知数量；
- 工具错误数量；
- 文件修改事件数量；
- 模型证据来源的现有安全表示。

公共报告禁止包含：

- 最终回答；
- 错误正文；
- 命令正文或输出；
- session ID；
- 本地相对或绝对路径；
- 用户名、环境变量或凭据。

旧公共报告继续可读。新报告的新增字段必须通过 JSON Schema 和隐私回归测试。

## 9. 原子性与恢复

- 证据文件使用同目录临时文件、刷新、关闭和原子重命名；
- 数据库任务结果、Agent 摘要和批次隔离证明在同一事务中提交；每个新版本的终态任务都必须有摘要行；
- 数据库提交失败时删除刚写入的证据文件；
- 恢复检查验证任务结果与 Agent 摘要的组合形状；
- 已越过 Provider 边界但结果未知的任务仍不得自动重放；
- 诊断详情丢失不改变已冻结的验证分数，但界面必须说明详情已清理或不可用。

## 10. 测试策略

全部自动化测试使用假 Provider，不调用真实模型。

### Node

- Codex item 到标准诊断的映射；
- Claude 可见字段到标准诊断的映射；
- 命令成功、失败、未知和退出码计数；
- error item 分类与文本上限；
- 路径、凭据、控制字符和超长文本脱敏；
- 未知字段、矛盾状态和恶意对象拒绝；
- `promptfoo-agent-v2` 单行协议与输出大小限制。

### Rust

- v2 响应严格解析和身份绑定；
- Provider success 与验证 success 分离；
- 证据文件原子写入和失败清理；
- 路径逃逸、重解析点和符号链接拒绝；
- 数据库迁移、旧数据库读取和批次原子检查点；
- 原始数据清理后仅保留安全摘要；
- 恢复时拒绝不一致证据。

### 桌面端

- 结果页分别显示 Agent 状态和验证状态；
- “Agent 已结束但测试失败”保持失败结论；
- 详情默认折叠并按需加载；
- 详情过期或损坏时使用稳定提示；
- 键盘、焦点、窄屏、200% 缩放和 axe 检查；
- DTO 和错误消息不泄漏 repository detail、凭据或路径。

### 报告与全仓

- 公共 JSON/HTML 报告只含允许的摘要字段；
- 旧报告兼容；
- 仓库测试、构建、格式、lint、schema、许可证和链接验证全部通过。

## 11. 完成条件

本功能完成必须同时满足：

1. CLI 编排层不再丢弃结构化 Agent 证据；
2. 假 Provider 能稳定复现“Agent 正常结束、无文件修改、验证失败”；
3. 结果页同时显示“Agent 已结束”和“任务验证失败”；
4. 本地展开详情能说明命令失败数、工具错误和最终回答；
5. 公共报告与运行列表不含任何诊断正文、路径、命令或 session ID；
6. 原始数据清理后摘要仍可读，正文明确显示不可用；
7. 旧数据库和旧报告仍可读取；
8. 所有测试均使用假 Provider，开发阶段真实模型调用数为零。
