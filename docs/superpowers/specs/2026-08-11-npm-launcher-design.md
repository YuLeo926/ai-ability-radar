# npm 轻量启动器设计

日期：2026-08-11
状态：已由用户逐段确认

## 1. 背景

AI 能力雷达目前提供 GitHub Pages、Windows 安装包、MSI 和便携 ZIP。源码启动和桌面安装适合不同用户，但仍缺少一条面向已经安装 Node.js 的用户的最短启动路径：

```text
npx ai-ability-radar
```

npm 包不承载桌面程序本体。它只负责取得与自身版本严格一致的 GitHub Release 便携版，完成独立完整性校验、本地缓存和启动。

## 2. 目标

- 提供 `npx ai-ability-radar` 一条命令启动桌面程序；
- npm 包版本与 GitHub 标签和便携资产版本严格一一对应；
- 首次下载后允许离线启动；
- 校验下载资产和解压文件，缓存损坏时安全修复；
- 不要求管理员权限，不写注册表，不安装系统服务；
- 不读取 GitHub、npm、Codex 或 Claude 登录凭据；
- 不上传遥测、运行记录、模型回答或本机环境信息；
- 初版只支持 Windows x64。

## 3. 非目标

- 不在 npm 包中内置完整桌面程序或便携 ZIP；
- 不从源码编译 Rust/Tauri 应用；
- 不自动改用 `latest`、其他标签或其他架构；
- 不允许用户指定任意下载地址、镜像或可执行文件；
- 不转发任意参数给桌面程序；
- 不替代 Windows 安装包、MSI 或直接下载的便携版；
- 不在自动测试中调用真实 Codex 或 Claude。

## 4. 方案选择

采用“版本锁定的轻量下载启动器”。

未采用的方案：

- npm 内置桌面程序：包体积大，与 GitHub Release 重复托管，更新和审核成本高；
- npm 从源码构建：要求 Rust、Tauri 和系统构建依赖，首次运行慢且失败面大；
- 永远下载最新 Release：同一 npm 版本会在不同时间运行不同桌面代码，无法复现。

## 5. 包结构

新增独立目录 `packages/launcher`，发布名为 `ai-ability-radar`。建议发布内容仅包括：

- `bin/ai-ability-radar.mjs`：命令入口；
- `lib/`：下载、校验、缓存、解压和启动模块；
- `extract.ps1`：固定参数的 Windows 解压脚本；
- `release-manifest.json`：版本、资产、外层哈希和解压文件清单；
- npm README、许可证和必要元数据。

启动器使用 Node.js 内置模块，初版不增加运行时 npm 依赖。与项目现有运行时口径一致，初版只接受 Node.js 22（最低 `22.22.0`）或 Node.js 24 LTS；`package.json` 的 `engines.node` 和运行时预检必须表达同一约束。`package.json` 使用严格的 `files` 白名单和 `bin` 映射，避免把桌面源码、测试夹具或本地文件发布到 npm。

## 6. 版本和资产契约

启动器从自身 `package.json` 读取版本，例如 `0.2.2`，并只接受严格稳定版语义版本。该版本唯一映射到：

- 标签：`v0.2.2`；
- 便携资产：`ability-radar_0.2.2_windows-x64-portable.zip`；
- 校验资产：`SHA256SUMS.txt`。

下载路径固定到 `YuLeo926/ai-ability-radar`。任何标签、文件名、版本或清单不一致都属于发布同步错误，启动器必须停止，不能回退到其他版本。

`release-manifest.json` 在 npm 发布前从已构建的 Release 资产生成并审查，至少包含：

- 清单格式版本；
- npm/桌面版本和 Git 标签；
- ZIP 文件名、字节数和固定 SHA-256；
- 便携根目录和可执行文件相对路径；
- 解压后允许存在的精确文件集合、字节数和 SHA-256。

下载的 `SHA256SUMS.txt` 必须与 npm 包内固定的 ZIP 哈希一致。校验表与 ZIP 来自同一 Release，因此校验表不能替代 npm 包中的独立固定值。

## 7. 运行流程

默认执行流程如下：

1. 验证平台为 Windows x64、Node.js 版本受支持、包版本和发布清单一致；
2. 定位 `%LOCALAPPDATA%/AI Ability Radar/launcher/v<version>/`；
3. 验证已缓存 ZIP、解压文件清单、关键路径和文件哈希；
4. 缓存完整时直接启动桌面程序；
5. 缓存缺失时下载固定版本的校验表和 ZIP；
6. 下载先进入随机临时文件，执行大小、来源和 SHA-256 校验；
7. 在启动器创建的随机临时目录中解压；
8. 拒绝路径穿越、绝对路径、链接/重解析点、重复目标、额外文件、缺失文件和哈希不符；
9. 验证成功后原子启用新的版本缓存；
10. 使用直接进程启动桌面可执行文件，确认进程已成功创建后退出启动器。

任何阶段失败都不得启动未验证文件。

## 8. 缓存与所有权

每个版本使用独立目录。缓存包含经过验证的 ZIP、解压后的应用目录和只作为性能提示的状态文件。状态文件本身不构成信任来源；最终判断必须回到 npm 内置清单和文件哈希。

同一版本的并发启动通过缓存根目录下的版本锁协调。锁必须用原子文件系统操作取得，等待时间有上限；等待者在锁释放后重新验证缓存。锁持有者只写自己的随机临时目录，最终通过原子重命名发布缓存。进程异常退出后，后续调用只能在确认锁已超时且重新验证缓存状态后回收锁，不能仅凭锁文件中的进程号删除其他调用的工作目录。

- 首次运行必须联网；
- 缓存有效时允许离线启动；
- 缓存损坏时优先从仍然有效的固定 ZIP 修复，否则重新下载；
- 下载或修复只写入随机临时路径，验证成功后再切换；
- 失败时保留原有有效缓存，只清理由本次调用创建且身份仍匹配的临时路径；
- 不自动删除其他版本；
- `--clear-cache` 只删除启动器拥有的缓存根目录并退出，删除前必须验证绝对路径、固定祖先和目录身份。

## 9. 网络与解压安全

- 初始 URL 固定为 HTTPS GitHub Release 地址；
- 不接受命令行 URL、环境变量镜像或配置文件覆盖；
- 重定向次数有上限，只允许 HTTPS GitHub/GitHubusercontent 目标；
- 校验表和 ZIP 分别设置合理的字节上限、连接超时和总下载超时；
- 流式写入和流式 SHA-256，避免把整个 ZIP 常驻内存；
- 不通过 shell 执行命令；
- 使用 `spawn` 直接调用 Windows PowerShell，以 `-NoProfile`、`-NonInteractive` 和固定 `extract.ps1` 运行，归档和目标目录作为独立参数传递；
- 解压前后都进行结构检查，最终只信任 npm 内置文件清单；
- 不在错误消息中回显临时绝对路径、请求签名参数或系统环境变量。

## 10. 命令和用户体验

初版只提供：

- `npx ai-ability-radar`：验证、必要时下载并启动；
- `npx ai-ability-radar --help`：显示简短中文帮助；
- `npx ai-ability-radar --version`：显示 npm 启动器版本；
- `npx ai-ability-radar --clear-cache`：安全清理启动器缓存并退出。

未知参数返回非零退出码，不转发给桌面程序。错误信息使用稳定的中文分类，包括：平台不支持、版本不同步、网络不可用、下载超时、资产过大、校验失败、缓存损坏、解压失败和程序启动失败。

若网络失败但缓存有效，启动器继续离线启动；若没有有效缓存，则明确提示首次运行需要联网。

## 11. 测试策略

自动测试全部使用临时目录、本地假 HTTPS/下载边界和假可执行文件，不调用真实模型。

### 单元与契约测试

- 严格版本、标签和资产文件名映射；
- 重定向、HTTPS、大小、超时和中断处理；
- 正确哈希、错误哈希、错误校验表和半包清理；
- 缓存命中、离线启动、缓存篡改和从固定 ZIP 修复；
- 路径穿越、链接/重解析点、重复、额外和缺失文件拒绝；
- 原子启用、并发运行和失败时保留旧缓存；
- `--help`、`--version`、`--clear-cache` 和未知参数；
- 启动成功、启动失败和错误信息脱敏。

### 发布包测试

- `npm pack --json` 检查精确文件白名单；
- 从生成的 `.tgz` 安装并执行全部命令测试；
- GitHub Windows 流水线执行缓存首次安装、二次命中、离线和损坏修复场景；
- 依赖审计、许可证清单和仓库契约验证继续保持通过。

## 12. 上线与回滚

上线顺序固定为：

1. GitHub Actions 生成 `v0.2.2` 草稿 Release；
2. 在干净 Windows 环境验收 EXE、MSI 和便携 ZIP；
3. 公开 GitHub Release；
4. 从最终资产生成并核对 npm 发布清单；
5. 运行完整测试和 `npm pack` 内容审计；
6. 用户完成 npm 登录；
7. 公开发布 `ai-ability-radar@0.2.2`；
8. 在无仓库环境实际执行一次 `npx ai-ability-radar@0.2.2`。

已发布版本不得覆盖。出现严重问题时将 npm 版本标记为弃用，并通过新的补丁版本修复；GitHub Release 保留可审计记录，不静默替换同名资产。

## 13. 完成条件

功能完成必须同时满足：

1. npm 包体不包含桌面二进制或便携 ZIP；
2. npm 版本只能启动严格对应的 GitHub Release 版本；
3. 首次下载、缓存命中、离线、损坏修复和清理均通过测试；
4. 下载 ZIP 与解压文件均由 npm 内置固定值验证；
5. 任意校验或路径检查失败时都不会启动程序；
6. npm 包内容、许可证、安全审计和 Windows CI 全部通过；
7. 干净 Windows 实机验收完成；
8. 发布后的真实 `npx` 验收成功；
9. 开发和自动验证阶段真实 Codex/Claude 调用次数为零。
